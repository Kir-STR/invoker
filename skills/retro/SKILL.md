# retro — движок эволюции правил

Каноническое имя вызова — `/invoker:retro`; в прозе — `ivk retro`.

Сводит наблюдения из реальной работы в кандидаты-правила и предлагает точечные правки. **Сам инструкции не правит** — единственный файл, который пишет retro, это стейджинг `.invoker/ideas_4_rules.md`. Применение промоций и удаление обработанных черновиков — отдельные шаги оператора (гейт). Парный always-on контекст — правило `.claude/rules/retro-loop.md` (если модуль `retro-loop` развёрнут).

## Источники наблюдений

- Черновики по веткам `.invoker/retro/<branch>.md` — их оставляют worktree-агенты после сессии (шаблон `.invoker/retro-template.md`).
- Память и транскрипт мастер-сессии — наблюдения про улучшение инструкций проекта.

## Протокол

1. **Собери идеи** в стейджинг `.invoker/ideas_4_rules.md` → секция «Активные кандидаты» (создай файл при отсутствии). Стейджинг лежит в `.invoker/`, а не в `.claude/rules/`, намеренно: Claude Code auto-load'ит **все** `.claude/rules/*.md` в контекст каждой сессии независимо от `globs`-frontmatter и gitignore-статуса — стейджинг там засорял бы контекст. Для каждой идеи проставляй источник явно: `мастер (YYYY-MM-DD)` или `ретро {branch} (YYYY-MM-DD)`. Если идея уже есть — наращивай счётчик независимых прецедентов `n`, не дублируй.

2. **Классифицируй** каждый активный пункт:
   - **promote → project-rule** — точечная правка `CLAUDE.md` / `GEMINI.md` / `AGENTS.md` / актуального файла в `.claude/rules/`. Критерий (любой): `n≥2`, принцип явно общий, либо высшая уверенность в полезности (high-conf-safety).
   - **promote → stage-rule** — новое или дополненное узкое правило в `.claude/rules/` (применимо к узкому окну: этап / тип задачи) + любое из условий promote выше.
   - **observation** — `n=1`, ждём повтора.
   - **stale** — observation висит ≥2 раундов `ivk retro` без новых прецедентов. Предложи reject или явное keep с обоснованием.
   - **discard** — лишнее / перекрытие, с обоснованием.

3. **Выведи оператору** таблицу `slug → категория → точная правка или обоснование`. Для каждого обработанного `.invoker/retro/<branch>.md` — пометка «предложено удалить» (cleanup — gated, см. ниже). Промоутнутые и отброшенные пункты убери из «Активных кандидатов» и оставь строку в «Логе обработки» `.invoker/ideas_4_rules.md`.

## Гейты — единственное изменение ФС по умолчанию — стейджинг

- **Не правь сам** `CLAUDE.md`, файлы в `.claude/rules/`, `GEMINI.md`, `AGENTS.md` и обработанные черновики `.invoker/retro/<branch>.md` — только предлагай. Единственный файл, который пишешь ты, — `.invoker/ideas_4_rules.md` (стейджинг).
- **Промоция — после явного подтверждения оператора.** Применение promote-правки — отдельный его шаг (через PR, если правка затрагивает чувствительные пути).
- **Cleanup черновиков — gated.** По умолчанию `.invoker/retro/<branch>.md` НЕ удаляются. Удаление или архив разрешены только после записи строки в «Лог обработки» + подтверждения оператора.
